# 场景规范：述职汇报模式（Report Mode）

> 不是一套新的视觉系统，而是一套新的**思考方式**。用已有的组件库，但按「汇报逻辑」规划和组装。

---

## 核心区别：演讲思维 vs 汇报思维

| 维度 | 演讲分享（现有） | 述职汇报（Report Mode） |
|------|---------------|---------------------|
| 目标 | 让人记住1-3个观点 | **证明一个结论成立** |
| 标题 | 短关键词 | **完整结论句（标题=这页的答案）** |
| 信息密度 | 每页2-3点 | **每页4-6点** |
| 阅读动线 | 视觉吸引→自由扫视 | **逻辑链引导→一步步推导** |
| 页面占满率 | 30-50% | **70-90%** |
| 核心组件 | 大字/留白/动效 | **流程图/架构图/数据+结论** |

---

## 生成前的思考框架（从 slides_maker 学习）

### Step 0：确定这页要回答什么问题

**在排版之前，先写下这页要回答的一个问题。** 标题就是这个问题的答案。

示例：
- 问题：用户为什么愿意付更高的价格？
- 标题：「B端额外付费的本质是购买超出基础价格之外的精准流量」

### Step 1：确定这页的论证结构

每页选一种论证结构（不是布局，是逻辑结构）：

| 论证结构 | 说明 | 适合内容 |
|---------|------|---------|
| **因果链** | A→B→C→结论 | 流程推导、归因分析 |
| **对比** | 旧方案vs新方案 | 方案升级、迭代说明 |
| **分层** | 高/中/低 或 一级/二级/三级 | 分类体系、优先级 |
| **验证** | 假设→方法→数据→结论 | 模型效果、实验结果 |
| **拆解** | 一个问题拆成多个子问题 | 复杂问题分析 |

### Step 2：确定信息组件搭配

根据论证结构，从已有组件库中选择搭配：

| 论证结构 | 推荐组件搭配 |
|---------|------------|
| 因果链 | 组件6(流程图) + 组件20(竖色条要点) + 组件3(洞察条) |
| 对比 | 组件42(Do/Don't) 或 组件52(对比表) + 组件3(洞察条) |
| 分层 | 组件16(分割线条目) + 组件15(数据大字) + 组件17(强调块) |
| 验证 | 组件19(指标行) + 截图容器(图表) + 组件51(Key Insight) |
| 拆解 | 组件54(编号网格) 或 组件40(编号主导卡片) + 组件3(洞察条) |

### Step 3：确定注意力引导

每页有且只有一个「视觉焦点」——用户第一眼应该看到的东西：

| 焦点类型 | 实现方式 |
|---------|---------|
| 核心数字 | 用组件15(数据大字)，字号是正文的4倍+ |
| 核心结论 | 用组件51(Key Insight)或组件17(强调块) |
| 关键图表 | 截图贴入，占页面40%+面积 |
| 核心流程 | 流程图中的关键节点用强调色 |

## 页面密度规则

### 允许的高密度排版

在汇报模式中，一页可以同时包含：
- 标题（结论句）
- 流程图或架构图
- 2-3个数据指标
- 1个图表截图
- 1个结论条

但必须有**层次**（不是平铺）：
- 标题区（10%）：最大字号，品牌色
- 主内容区（70%）：多组件混排
- 结论区（20%）：洞察条或Key Insight

### 多组件混排的规则

当一页有多个组件时：
1. **左右分栏**：左侧放过程/推导，右侧放结论/数据
2. **上下分区**：上方放论证，下方放结论
3. **主从关系**：一个组件占60%面积为主，其余为辅
4. 不允许3个以上等大组件平铺（那就是堆砌不是设计）

## 标题写法（最重要的改变）

### 演讲风标题 vs 汇报风标题

| 演讲风（❌ 汇报模式禁用） | 汇报风（✅ 必须这样写） |
|----------------------|-------------------|
| Core Features | 智选业务的流量售卖单价达到¥50-200，显著高于搜畅业务 |
| 增长趋势 | Q3各项核心指标全面提升，核心归因于搜索重构上线 |
| 技术架构 | 基于正样本构建的质量分层模型AUC达0.73，具备较好区分能力 |
| 行业定义 | AI漫剧的单集成本降至传统模式1/10，制作周期从月级压缩至天级 |

**规则：标题读完，就能知道这页的结论是什么，不需要看正文。**

---

## 主题色使用（仍然用现有4套）

汇报模式推荐：
- **深空蓝**：最正式，适合管理层汇报
- **石墨灰**：适合技术类/方法论汇报

在深色页中使用强调色做信息分层：
- accent色 = 核心结论/标题
- positive色 = 正向数据/达标
- negative色 = 风险/问题/未达标
- 白色 = 正文内容

## 和演讲分享场景的组件复用

不需要新组件，用已有组件但**组合方式不同**：

| 组件 | 演讲中怎么用 | 汇报中怎么用 |
|------|-----------|-----------|
| 组件6(流程图) | 独占一页，3-4步 | 页面一部分，可5-7步 |
| 组件15(数据大字) | 独占一页做冲击 | 和其他组件混排在一页 |
| 组件3(洞察条) | 页面底部总结 | 论证链的最终结论 |
| 组件16(分割线条目) | 独占一页做列表 | 页面左半部分的要点列表 |
| 组件51(Key Insight) | 独占一页做金句 | 混排在分析内容旁边 |
| Layout K(表格) | 独占一页 | 和文字分析并列 |



---

## 适用场景

- 季度/年度述职
- 数据分析专题汇报
- 方案评审/策略提案
- 项目复盘
- 模型效果汇报
- 业务分析专题

## 不适用

- 轻松的团队分享（用演讲模式）
- 产品推广（用演讲模式）
- 对外宣讲（用演讲模式）
