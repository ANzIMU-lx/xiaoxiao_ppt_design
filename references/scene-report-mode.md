# 场景规范：述职汇报模式（Report Mode）

> 信息量参考咨询公司，排版质感参考我们的设计系统。高密度 ≠ 塞满，而是**信息点多+间距精致**。

---

## 核心定位

**既不是演讲风的「一页一句话」，也不是丑PPT的「全塞满」。**

而是：每页有 4-6 个信息点，但每个信息点之间有精致的间距和层次区分。看起来信息量很大，但不会觉得挤。

参考标杆：BOSS直聘的数据分析汇报PPT——信息密度高，但排版有设计感。

---

## 和演讲模式的3个核心区别

| 区别 | 演讲模式 | 汇报模式 |
|------|---------|---------|
| 标题 | 2-5个词 + 英文Label | **完整结论句（15-30字）** |
| 每页信息点 | 2-3个 | **4-6个** |
| 组件使用 | 一个组件独占一页 | **2-3个组件混排在一页** |
| 每个要点文本量 | 1行标题+0-1行描述 | **1行标题+2-3行描述（含数据）** |
| 数据呈现 | 光秃秃的大数字 | **数字+上下文解释+对比基线** |

其他不变——同样的主题色、同样的字体、同样的组件库、同样的动画系统。

---

## 生成前的思考框架

### 每页先问自己3个问题

1. **这页要回答什么问题？** → 答案就是标题
2. **用什么逻辑证明？** → 因果链/对比/分层/验证/拆解
3. **视觉焦点在哪？** → 一页只有一个最抢眼的东西

### 5种论证结构 → 组件搭配

| 论证结构 | 适合内容 | 组件搭配建议 |
|---------|---------|------------|
| 因果链 | 流程推导、归因 | 横向流程图 + 竖色条要点 + 洞察条 |
| 对比 | 方案升级、AB测试 | Do/Don't + 对比表 + Key Insight |
| 分层 | 分类体系、优先级 | 分割线条目 + 数据大字 + 强调块 |
| 验证 | 模型效果、实验 | 指标行 + 图表截图 + Key Insight |
| 拆解 | 复杂问题拆分 | 编号卡片网格 + 洞察条 |

## 标题写法

**标题 = 这页的结论，不是这页的主题。**

| ❌ 演讲风标题 | ✅ 汇报风标题 |
|-------------|------------|
| 用户增长 | 次日留存较上月提升5.1pp，主因新手引导优化 |
| 技术方案 | 基于正样本构建的质量分层模型AUC达0.73 |
| 市场分析 | 高质量牛人存在明确的质量溢价，可接受成本¥6-10 |
| 下一步计划 | Q2重点投入留存优化，预计带来¥320万增量收入 |

## 排版规则（精致 ≠ 塞满）

### 间距要求（比演讲模式小，但不能没有）

| 元素间 | 演讲模式 | 汇报模式 |
|--------|---------|---------|
| 标题→内容 | 28-40px | **20-28px** |
| 组件间 | 20-32px | **16-24px** |
| 组件内padding | 24-32px | **14-20px** |
| 行间距 | 1.7-1.9 | **1.5-1.7** |

**关键：间距缩小了，但不是0。每个组件之间仍然能看到「空气」。**

### 信息密度硬性要求

| 要素 | 最低标准 |
|------|---------|
| 每个要点描述 | **≥2行**，需包含数据支撑或逻辑解释 |
| 数据指标 | 必须附带**一句上下文解释**（不能光秃秃放数字） |
| 策略/路径框 | 需写清**具体步骤链 + 产出物** |
| 底部洞察条 | ≥1.5行，说清 so what 和具体影响量级 |
| 正文字号 | ≥ 1.08rem（演示可读；根字号见 brand-dna） |
| 页标题 | ≥ 2.1rem |
| 内容区 | 铺满约 96–98vw × 88–94vh，无溢出裁切 |
| 标题字号 | ≥ 1.1rem |

**核心原则：每个信息模块既有结论又有支撑。「减少触达」不够，要写「减少触达 3200万→2832万(-368万次/月)」。**

### 多组件混排规则

一页放 2-3 个组件时：

1. **主从关系明确** — 一个占 60% 为主视觉，其他为辅
2. **不要3个等大组件平铺** — 那就是堆砌
3. **左右分栏时，左侧放推导过程，右侧放结论/数据**
4. **底部留一个洞察条/Key Insight 做收束**
5. **每个分栏底部可加「策略逻辑」段落**，用1-2句话解释为什么这么做

### 页面结构（三区法）

```
┌─────────────────────────────────────┐
│ 标题区 (8-10%)                       │  ← 结论句 + 论证结构标签(可选)
├─────────────────────────────────────┤
│                                     │
│ 主内容区 (72-80%)                    │  ← 2-3个组件混排
│                                     │
├─────────────────────────────────────┤
│ 收束区 (12-18%)                      │  ← 洞察条 / Key Insight / 指标行
└─────────────────────────────────────┘
```

## 推荐页面结构模板

### 三栏逻辑型（P2风格，适合背景/拆解类页面）

```
左栏(30%)    中栏(40%)       右栏(30%)
数据面板     矛盾/要点拆解    路径/方案
 - 大数字     - border-left色条  - 步骤卡片
 - 说明文字   - 标题+2行描述    - 具体产出物
```

**要点**：左栏放硬数据（大字号+解释），中栏放分析（每点≥2行描述），右栏放行动。

### 左分析+右数字型（P3风格，适合验证类页面）

```
左栏(55-60%)           右栏(40-45%)
因果链流程              核心大数字
 → 详细拆解卡片(×3)     → 辅助KPI(×2-3)
   每卡片≥2行描述         每个数字+说明
```

**要点**：左栏流程图做引导，下方白色卡片展开细节；右栏大数字做视觉锚点。

### 对比分栏型（P6风格，适合方案对比页面）

```
左栏(50%)              右栏(50%)
人群A / 方案A           人群B / 方案B
 - 数据行(×4-5)         - 数据行(×3-4)
 - 策略逻辑段落          - 策略逻辑段落
                        - 汇总框
```

**要点**：每行数据都有标签+数值+单位；底部加策略逻辑解释为什么这么做。

## 视觉焦点引导（每页只设一个焦点）

| 焦点类型 | 实现方式 | 用什么组件 |
|---------|---------|----------|
| 核心数字 | 字号是正文4倍+ | 组件15(数据大字) |
| 核心结论 | 用accent色边框/背景 | 组件51(Key Insight) |
| 关键流程节点 | 其中一个节点用accent色 | 组件6(流程图)变体 |
| 图表中的重点 | 给截图加标注箭头 | 截图容器+文字标注 |

焦点之外的内容用**次要色(text-secondary)**弱化，不抢视线。

---

## 色彩使用（信息分层）

在暖彩三色基础上，汇报模式额外用色彩做**信息类别区分**：

- **accent色** = 核心结论/关键数字
- **positive色** = 正向/达标/增长
- **negative色** = 风险/未达标/下降
- **text-primary** = 正文
- **text-secondary** = 补充说明

同一页中最多出现 **accent + positive/negative 之一**，不要同时出现3种强调色。

## 组件使用方式变化

| 组件 | 演讲模式 | 汇报模式 |
|------|---------|---------|
| 流程图(6) | 独占一页，3-4步 | 页面上半部分，可5-7步 |
| 数据大字(15) | 独占一页冲击 | 和流程图/表格并列 |
| 洞察条(3) | 页面底部可选 | **每页必须有**，作为收束 |
| Key Insight(51) | 独占一页金句 | 混排在分析内容旁边 |
| 表格(K) | 独占一页 | 和文字分析并列 |
| 条目列表(16) | 独占一页 | 页面左半部分 |
| 指标行(19) | 底部总结 | 和流程图/图表混排 |
| **图表(56-60)** | **偶尔使用** | **凡有数据必须画图** |

### 图表使用硬性规则（汇报模式）

1. **凡是有对比数据、趋势数据、占比数据，必须生成 Chart.js 图表**，不能只用数字罗列
2. 图表配色跟随当前主题三色系（青绿/玫瑰/暖金）
3. 每个图表下方必须跟洞察条
4. 图表类型选择：
   - 多组对比 → 柱状图(56) / 分组柱状图(59)
   - 时间趋势 → 折线图(57)
   - 构成占比 → 环形图(58)
   - 行内趋势 → 迷你SVG图(60)
5. 数据行中也可嵌入迷你SVG趋势线，增加数据可读性

---

## 适用场景

- 季度/年度述职
- 数据分析专题汇报
- 方案评审/策略提案
- 项目复盘
- 模型效果汇报

## 不适用

- 轻松的团队分享（用演讲模式）
- 产品推广（用演讲模式）
- 对外宣讲（用演讲模式）
