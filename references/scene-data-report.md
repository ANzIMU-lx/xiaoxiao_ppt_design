# 场景规范：数据分析报告

## 基调

专业、严谨、数据驱动、结论先行、信息密度高

## 受众

数据分析师、产品经理、业务方、管理层

## 推荐主题

暖彩三色（唯一主题）

## 核心原则（区别于团队分享）

### 内容保留原则

1. **保持内容高度严谨，尽量呈现原文** — 数据报告不是总结PPT，关键论述必须完整
2. **做内容优化取舍，不要全盘照搬** — 全写肯定没错，但不是我们想要的效果。取舍标准：是否支撑核心结论
3. **如果原文含表格，保留表格格式** — 不要把表格改成文字描述
4. **关键数据必须带上下文** — 不是只放数字，要有同比/环比/来源/趋势方向
5. **结论先行** — 每页第一眼看到的必须是结论/洞察，然后才是支撑数据

### 信息密度规则

| 场景 | 每页核心信息点 | 正文最大行数 | 允许密度 |
|------|-------------|------------|---------|
| 团队分享 | 2-3 | 4行 | 低 |
| **数据报告** | **4-5** | **6-8行** | **高** |
| 述职汇报 | 3-4 | 5行 | 中高 |

数据报告允许单页承载更多信息，但必须有视觉层次（标题/正文/数据/结论用不同字号字重区分）。

### 排版风格：咨询风 × 设计系统结合

**避免两个极端：**
- ❌ 纯咨询卡片风（全是边框+表格，像Word贴进PPT）
- ❌ 纯设计风（大留白+一句话，看不到数据）

**正确的结合方式：**
- 每页有一个「视觉锚点」— 大数字/图表/色块，占页面30%视觉权重
- 剩余70%是严谨的文字内容 — 要点列表/正文段落/表格
- 标题用设计系统字体（Playfair），正文用高可读性排版
- 关键结论用洞察条/色块强调，不是隐藏在正文里

## 页面节奏（推荐 12-20 页）

数据报告页数多但不应该每页都一样，需要节奏变化：

| 类型 | 占比 | 布局推荐 | 说明 |
|------|------|---------|------|
| 封面/章节分隔 | 15% | D/D2 | 呼吸，大留白 |
| 核心数据页 | 20% | M/M2 | 数据大字冲击 |
| 分析内容页 | 40% | **Q(新)** / A / K | 高密度咨询风内容 |
| 图表/对比页 | 15% | H / I | 可视化数据 |
| 结论/建议页 | 10% | B / P | 步骤/观点 |

## 推荐布局组合

| 页面内容 | 首选布局 | 备选 |
|---------|---------|------|
| 核心KPI总览 | M1/M2(大数字) | G2(大小卡) |
| 行业定义/概念解释 | A1(左文右表格) | Q(咨询密集) |
| 技术/流程说明 | N(条目列表) | B(大数字步骤) |
| 区域/分类对比 | K(表格) / O(色块分区) | E(标签) |
| 增长趋势 | H(图表+洞察) | M2(双指标) |
| 案例分析 | Q(咨询密集) | N(条目+数据) |
| 痛点vs机会 | O(色块分区) / I(对比) | — |
| 政策/时间线 | C(时间轴) | N(条目) |
| 入局建议 | B(大数字步骤) | P(观点+证据) |

## 特殊规则

1. **每个数据页必须有洞察条** — 不是可选项，是强制项
2. **表格不简化** — 原文有4列5行，PPT就做4列5行，不要删列
3. **长段落拆分但不精简** — 3行以上的段落拆成2-3个要点(•)，但内容不减
4. **来源标注** — 关键数据后面用小字标注来源（如 "来源：DataEye 2025"）
5. **趋势方向可视化** — 正向用 ▲+绿色，负向用 ▼+红色，不要只写"+23%"
